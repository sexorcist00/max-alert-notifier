# max-alert

Сторож для одного чата в мессенджере MAX: ловит сообщение по ключевому слову и поднимает на телефоне
громкую тревогу — звук в цикле, вибрация, уведомление с кнопкой **СТОП**.

Работает в Termux на самом телефоне. Ничего, кроме телефона, не нужно: ни сервера, ни бота в чате,
ни прав администратора.

```
MAX (ваш аккаунт)  ──websocket──▶  python -m max_alert  ──▶  matcher  ──▶  Termux:API
                                                                            ├─ termux-media-player  (звук в цикле)
                                                                            ├─ termux-vibrate       (вибрация)
                                                                            └─ termux-notification  (экран + кнопка СТОП)
```

---

## Важно перед началом

Библиотека [PyMax](https://github.com/MaxApiTeam/PyMax) работает через **внутренний, неофициальный API
MAX** — тот же, которым пользуется веб-версия. Официальный Bot API здесь не подходит: чтобы читать
групповой чат, бот должен быть добавлен в него и быть администратором.

Что это значит на практике:

- API может измениться без предупреждения — тогда сторож перестанет ловить сообщения, пока не выйдет
  обновление библиотеки;
- использование может нарушать условия сервиса, теоретический риск блокировки аккаунта существует;
- файл сессии `cache/main.db` — это **живой ключ от вашего аккаунта MAX**. Не выкладывайте его, не
  копируйте в облако, держите репозиторий приватным.

Это осознанный выбор: другой способ читать чужой чат без прав администратора отсутствует.

## Установка (Termux)

Нужны сам Termux и **приложение Termux:API** — это два разных приложения, и без второго не будет ни звука,
ни вибрации, ни уведомлений. Ставить оба из одного источника (F-Droid), иначе Android не даст им общаться.

```bash
pkg update && pkg upgrade
pkg install python git termux-api
git clone <URL этого репозитория> ~/max-alert
cd ~/max-alert
pip install -e .
```

Проверка, что Termux:API отвечает (должно завибрировать):

```bash
termux-vibrate -d 500
```

Если команда «висит» или молчит — откройте приложение Termux:API и выдайте ему разрешения; без этого
дальше идти нет смысла.

## Настройка

```bash
cp config.example.toml config.toml
nano config.toml
```

Минимум, что нужно поменять: `phone` (ваш номер) и `keywords` (что считать тревогой). `chat_ids`
заполняется на следующем шаге, когда станет известен id чата.

Проверить конфиг, ничего не запуская:

```bash
python -m max_alert --check-config
```

## Первый запуск и авторизация

```bash
python -m max_alert --list-chats
```

При первом запуске MAX пришлёт SMS-код — введите его в терминале. Сессия ляжет в `cache/main.db`, второй
раз код не спросят. Команда напечатает список чатов:

```
1234567890   CHAT   Диспетчерская смена
9876543210   CHAT   Курилка
```

Первое число — это `chat_id`. Впишите его в `config.toml`:

```toml
chat_ids = [1234567890]
```

Если нужного чата в списке нет (так бывает с каналами), запустите режим наблюдения — он печатает каждое
входящее сообщение и никогда не звонит:

```bash
python -m max_alert --discover
```

Напишите что-нибудь в нужном чате и возьмите `chat_id` из строки лога. Оттуда же берётся `sender` — если
тревогу должен поднимать только конкретный человек, впишите его id в `from_senders`.

Права на сессию стоит закрыть:

```bash
chmod 600 cache/main.db
```

## Проверка тревоги

Отдельно от MAX, чтобы убедиться, что телефон вообще умеет звенеть так, как нужно:

```bash
python -m max_alert --test-alarm
```

Должно: подняться громкость, заиграть сигнал по кругу, пойти вибрация, всплыть уведомление с кнопкой
**СТОП**. Нажатие на кнопку (или на само уведомление) гасит тревогу и возвращает прежнюю громкость.
Если не нажать — тревога сама смолкнет через `loop_seconds`.

Проверить, что конкретный текст считается тревогой (звенит только при совпадении):

```bash
python -m max_alert --simulate "объявлена тревога в третьем секторе"
```

## Постоянный запуск

```bash
./run.sh
```

`run.sh` берёт wake-lock (Android не усыпит процессор) и перезапускает сторожа, если тот упал.
Останов — `Ctrl+C`.

Автозапуск после перезагрузки телефона — через приложение **Termux:Boot** (F-Droid):

```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/start-max-alert.sh <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
exec ~/max-alert/run.sh
EOF
chmod +x ~/.termux/boot/start-max-alert.sh
```

## Huawei: без этого сторож проживёт минут двадцать

EMUI закрывает фоновые приложения агрессивнее большинства прошивок, и Termux — первый кандидат.
Пройдите все пункты, иначе тревога однажды просто не прозвенит:

1. **Настройки → Батарея → Запуск приложений** → найти Termux → переключить на **«Управлять вручную»** и
   включить все три переключателя: *автозапуск*, *косвенный запуск*, *работа в фоновом режиме*.
   То же самое для **Termux:API** и **Termux:Boot**.
2. **Настройки → Батарея** → выключить **«Закрывать энергоёмкие приложения»** (может называться
   «Оптимизация энергопотребления» / «Автозакрытие приложений»).
3. Открыть список недавних приложений, потянуть карточку Termux вниз и **закрепить её замком**.
4. **Настройки → Приложения → Termux → Уведомления** — разрешить; уведомление тревоги приходит через них.
5. Оставить экран Termux с активным wake-lock: в шторке у Termux есть строка `Acquire wakelock`,
   `run.sh` берёт его сам.

Отдельно: если ваша EMUI построена на **Android 12 и новее**, система дополнительно убивает «фантомные»
дочерние процессы Termux. Полностью это отключается только через adb с компьютера:

```bash
adb shell settings put global settings_enable_monitor_phantom_procs false
```

Компьютера нет — не страшно: цикл перезапуска в `run.sh` поднимет процесс обратно, но между падением и
подъёмом сообщение может быть пропущено. Версию Android смотреть в **Настройки → О телефоне → Общая
информация**.

## Если «Не беспокоить» глушит сигнал

Звук играет по стриму *music* (так работает `termux-media-player`), а режим «Не беспокоить» может его
приглушить. Признак: `--test-alarm` вибрирует и показывает уведомление, но не слышно.

Варианты, по возрастанию сложности:

1. Добавить Termux в исключения «Не беспокоить»: **Настройки → Звуки → Не беспокоить → Исключения**.
2. Голосом по стриму *alarm* вместо звукового файла: `termux-tts-speak -s ALARM "тревога"` — этот стрим
   режим «Не беспокоить» обычно не трогает. Проверьте руками; если помогает, скажите — добавлю флагом
   в конфиг.
3. Отдать звонок MacroDroid'у: он умеет играть по стриму *alarm* и перебивать DND. Termux дёргает его
   через `am broadcast -a <ваш intent>`, а MacroDroid ловит триггером «Intent Received».

Специально не реализовано заранее: пока не доказано, что первый вариант не работает, второй инструмент
в схему тащить незачем.

## Логи и диагностика

```bash
tail -f logs/max-alert.log
```

- `logged in as user … chats known` — авторизация прошла;
- `watching chat … ('Название')` — фильтр чата встал правильно;
- `no chat filter configured` — тревогу поднимет **любой** чат, впишите `chat_ids`;
- `match in chat …` — сообщение поймано, дальше идёт `ALARM:`;
- `disconnected from MAX` → `reconnecting in Ns` — обрыв связи, клиент сам переподключается с растущей
  паузой;
- `match ignored (cooldown or already seen)` — второе срабатывание внутри `cooldown_seconds` подавлено.

По временным меткам `match in chat` и времени сообщения в MAX меряется реальная задержка.

Подробный лог: `python -m max_alert -v`.

## Команды

| Команда | Что делает |
| --- | --- |
| `python -m max_alert` | основной режим: слушает чат и звонит |
| `python -m max_alert --check-config` | проверяет config.toml и выходит |
| `python -m max_alert --list-chats` | печатает id, тип и название всех чатов |
| `python -m max_alert --discover` | логирует каждое входящее сообщение, не звонит |
| `python -m max_alert --simulate "текст"` | прогоняет текст через матчер, звонит при совпадении |
| `python -m max_alert --test-alarm` | звонит прямо сейчас, без подключения к MAX |
| `python -m max_alert -v` | то же, но с подробным логом |
| `./run.sh` | wake-lock + автоперезапуск |
| `python tools/make_alarm_sound.py` | пересобрать `assets/alarm.wav` |

## Настройки config.toml

| Ключ | Значение |
| --- | --- |
| `max.phone` | номер вашего аккаунта MAX, в международном формате |
| `max.work_dir`, `max.session_name` | где лежит файл сессии |
| `watch.chat_ids` | какие чаты слушать; пусто — все |
| `watch.chat_title_contains` | вместо id: чаты, в названии которых есть подстрока |
| `watch.keywords` | ключевые слова (подстрока, регистр по умолчанию не важен) |
| `watch.regex` | регулярное выражение; если задано — имеет приоритет над `keywords` |
| `watch.case_sensitive` | учитывать регистр |
| `watch.from_senders` | id отправителей, которым разрешено поднимать тревогу; пусто — любым |
| `watch.ignore_own_messages` | не реагировать на свои же сообщения |
| `alarm.sound` | файл сигнала; можно указать системный, например `/system/media/audio/alarms/Argon.ogg` |
| `alarm.volume` | громкость стрима music, 0–15 (обрезается по максимуму устройства) |
| `alarm.loop_seconds` | предел звона, если никто не нажал СТОП |
| `alarm.vibrate_ms` | длительность вибрации; 0 — выключить |
| `alarm.cooldown_seconds` | сколько молчать после срабатывания, чтобы один инцидент не звонил дважды |

```bash
pip install -e ".[dev]"
```

Тесты офлайновые и детерминированные: матчер, антидребезг, разбор конфига. Всё, что касается звука и
